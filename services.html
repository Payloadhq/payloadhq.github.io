callx402 hosted payment diagnostics

$0.10 to $0.50 USDC · per action · USDC on Base via x402

Solves: x402 payment failed, facilitator settlement failed, paid but the result never arrived, unsure whether a retry is safe, possible duplicate payment.

Hosted diagnostic actions (diagnose, failure_classification, preflight, settlement_interpretation, resolve, duplicate_payment_risk, recover) that return structured evidence and an explanation. A free quote endpoint returns the exact price before any payment: GET https://payload-rail.fly.dev/v1/callx402/quote. Invoke with POST https://payload-rail.fly.dev/v1/callx402/actions/{action}, or through the MCP server io.github.payload-tools/callx402.

How payment works: quote first (free), then pay per action. Call an action unpaid to get its x402 v2 402 challenge with the exact USDC amount and payTo on Base. Pay from your own wallet, then redeem the original quote with the payment tx hash plus an EIP-191 signed authorization from the paying wallet; the rail verifies the payment exactly once on-chain and returns the result. Settlement runs through Payload's signed-redemption flow, not a generic x402 facilitator, so facilitator-only clients cannot complete a hosted purchase. The free local MCP tools in the npm package are the no-payment alternative: read-only diagnostics that never move money.

Limits: no guaranteed recovery and no diagnosis of every failure is promised. Settlement uses Payload's signed-redemption contract rather than the standard facilitator flow.

Veyline payment preflight and spending governance

Free evaluation · paid plans from $99/mo · Stripe

Solves: AI agent overspend, agent payment needs approval before it runs, no spending limits on a payment enabled agent.

Signed, scoped, expiring allow, deny, or escalate decisions on proposed agent payments, plus status and usage reporting. Get a free rail key at the console and call POST https://payload-rail.fly.dev/v1/a2a, or use the MCP server io.github.payload-tools/veyline-mcp.

Limits: an authorization layer does not guarantee protection against every attack or prevent every duplicate payment. Noncustodial: Payload does not hold customer funds. Subscriptions are sold through a human Stripe checkout.

RevRule entitlement and payout verification

$0.01 USDC · public evaluate · license $99 one time

Solves: payout does not match amount owed, revenue share split needs verification, royalty or affiliate payout dispute.

Programmable revenue graphs that compute what is owed, keep an entitlement ledger, and verify on-chain Base USDC payout evidence against it. The keyless public evaluate endpoint runs a fixed demo graph: POST https://payload-rail.fly.dev/v1/x402/public/evaluate. A free console key runs your own graphs, and the MCP server is io.github.payload-tools/revrule-mcp. A public payout evidence record is discussed in x402 Foundation issue 3758.

Integrating directly? The RevRule integration reference has the complete graph spec and every required event field, with examples verified against the live API.

Limits: RevRule does not execute payments and never holds funds.
