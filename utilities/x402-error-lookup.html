Code families covered as patterns

invalid_exact_svm_payload_transaction_

About twenty variants share this prefix; the suffix names the specific instruction or account at fault. Treat the suffix as the diagnosis: rebuild the transaction correcting the named element, and simulate locally before resubmitting.

invalid_batch_settlement_evm_

The batch-settlement scheme defines its own family under this prefix. The suffix names the failing element of the batch; the verify-then-settle checks in this table apply the same way.

invalid_upto_svm_ / settle_upto_svm_

The upto scheme on Solana defines invalid_upto_svm_ codes for payment requirements, payload, channel, and settlement failures, plus settle_upto_svm_ codes for onchain and confirmation failures. Settlement-prefixed codes follow the same rule as the other settle_ codes: confirm the transaction before paying again.

Questions

Where do I find my error code?

In the facilitator's JSON response: invalidReason when verification fails, errorReason when settlement fails. Paste the whole response into the lookup above and it will find the code in it.

Is it safe to retry a failed x402 payment?

It depends on the code, which is what the retry verdict in each result is for. Authorization and requirements failures are safe to retry after the named fix. Settlement failures are different: the payment may already have landed, so confirm the transaction onchain before paying again.

Why does my code start with invalid_exact_evm_permit2?

Your token settles through Permit2 instead of EIP-3009. Permit2 has a parallel code family, and one member matters most: invalid_exact_evm_permit2_payload_allowance_required means the one-time Permit2 approval has not been granted yet, so submit that approval transaction first.

What if my code is not listed?

Some families are covered as patterns rather than individual codes: Solana exact transaction variants, batch-settlement codes, and Solana upto codes. If your code matches none of the patterns, capture the full exchange and treat it like unknown_error: report it with the network, scheme, and error field included.
